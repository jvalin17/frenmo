# Requirements: Installment Settlements + Friends Balance Dashboard

> Generated by /requirements on 2026-10-11
> Mode: standard
> Scope: feature addition
> Depends on: rup-split.md (core settlement + friends system)

## Problem Statement

Users can't make partial payments toward a debt. The current settle-up is all-or-nothing. Users also can't see a per-friend breakdown of what they owe/are owed across all groups, with payment history.

## Features

### F1: Installment Settlements
**Priority:** Must-have

A user can record a partial payment toward a debt. The remaining balance updates accordingly.

**User stories:**
- As a user, I want to pay part of what I owe (e.g., $1,000 of $3,334), so I don't have to settle the full amount at once.
- As a user, I want to see payment history per debt (who paid how much, when), so I can track progress toward full settlement.
- As a user, I want to see the remaining balance after each payment, so I know how much is left.

**Behavior:**
- Settlement form accepts any amount ≤ remaining balance
- Each payment is recorded as a separate settlement expense (existing model)
- Settle-up section shows remaining balance after partial payments
- Payment history visible per debt (date, amount, running balance)
- Slide-to-settle triggers full settlement; manual amount input allows partial

**Data model:**
- No new tables needed — settlements are already `Expense(expense_type='settlement')`
- Payment history derived from settlement expenses between two users in a group

### F2: Friends Balance Dashboard
**Priority:** Must-have

The friends tab shows per-friend balances across all shared groups, with group-level breakdown and payment history.

**User stories:**
- As a user, I want to see how much I owe/am owed by each friend across all groups, so I have a single view of all debts.
- As a user, I want to see the breakdown per group (e.g., "$500 from Oregon Trip + $200 from Groceries"), so I understand where the balance comes from.
- As a user, I want to see payment history per friend (each settlement with date and amount), so I can track what's been paid.

**Behavior:**
- Friends page shows each friend with:
  - Net balance (total owed/owing across all groups)
  - Group breakdown: list of shared groups with per-group balance
  - Payment history: list of settlements between the two users (date, amount, group)
- Expandable/collapsible per friend

### F3: Auto-Friendship on Group Join
**Priority:** Must-have

When a user joins a group, they automatically become friends with all existing group members. The friendship relationship is unique (no duplicates).

**User stories:**
- As a user, I don't want to manually add friends who are already in my group — it should happen automatically.

**Behavior:**
- On group join (invite link or add-from-friends), create friendship records between the new member and all existing members
- Skip if friendship already exists (unique constraint)
- Existing friendship creation paths still work (manual add)

## Boundaries

- No payment links or external payment integrations
- Settlement amounts in same currency as the group
- Payment history is read-only (settlements can be deleted via existing delete flow)

## Dependencies

- Existing `Expense(expense_type='settlement')` model
- Existing `Friendship` model
- Existing `get_group_balances` + `simplify_debts` for per-group balances
- Existing `get_overall_balances` for cross-group view (needs enhancement for per-group breakdown)
